# 题目共享与审批

依据用户2026年10月22日补充的第二点需求：需求者先申请、出题者批准，或由出题者主动开放权限。两种方式都只授权用于需求者指定的一份问卷。

## 授权范围

每条授权固定四个编号：题目、具体版本、需求者、目标问卷。v1获准用于问卷A，不代表能导入问卷B，也不代表自动获得v2。目标问卷必须属于需求者，并在申请、主动授权和批准时处于草稿状态。已发布问卷仍不能增加或替换题目。

题目原作者可以新增原题版本；历史内容不可覆盖。共享接收者不能将题目派生为独立题目、保存为个人常用题或转授给其他用户，避免绕过单份问卷范围。可以将获准版本的引用整理进个人题库，但最终导入时仍逐次检查目标问卷授权。

共享使用权不含回答查看权。统计继续只汇总当前用户自建问卷。原作者可查看引用问卷的名称、编号和状态，不能因此管理它或查看其回答。

## 需求者申请

1. 创建自己的问卷草稿，向出题者取得常用题目的编号及版本号。出题者可在版本详情找到这些信息；普通填写链接不开放整卷题目预览。
2. 进入“题目与题库 → 共享申请与审批”，填写题目编号、版本号、目标问卷及可选说明。
3. 提交后显示“待审批”。此时不能查看源题正文、加入题库或导入问卷。
4. 获准后，在指定问卷的选题页选入该版本。申请其他问卷或版本时需另行提交。

## 出题者处理

在“共享申请与审批”核对需求者、目标问卷名称与编号、题目版本、申请说明，选择批准或拒绝。也可直接在自己的题目版本页填写需求者用户名和其草稿问卷编号，主动开放当前选定版本的使用权；需求者无需先发申请。后端核对问卷归属，不能将第三人的问卷冒充需求者的问卷。

| 当前状态 | 出题者操作 | 结果 |
| --- | --- | --- |
| 待审批 | 批准 | 仅指定版本、指定问卷获准 |
| 待审批 | 拒绝 | 不开放权限，保留拒绝记录 |
| 已授权 | 撤销 | 阻止后续源题访问或导入（其他仍有效授权不受影响） |
| 已拒绝或已撤销 | 需求者重新申请 | 创建新记录，保留旧记录 |

重复提交同一有效申请复用原记录；同一版本、需求者、问卷最多有一条待审批或已授权记录，MongoDB部分唯一索引约束并发。审批同时匹配原状态，过期页面不会把已拒绝或已撤销记录重新批准。主动授权遇到待审批申请时直接批准原申请，保留申请来源。

## 数据与兼容性

新增question_shares保存申请、状态、版本、需求者、目标问卷和处理人/时间。旧question_items.shared_with保留为历史兼容字段，已不作为授权依据，不自动转换成对需求者所有问卷的许可。第一阶段问卷和答案结构保持不变。

撤销不删除已导入的问卷内容或历史回答，也不停止已有问卷的填写和统计；它禁止新增导入和从源题库取用。撤销后同一用户若仍有其他问卷的有效授权，仍可查看相应已授权版本，但不能再导入被撤销的目标问卷。过去已经形成的独立派生题目不自动删除。

权限检查与问卷写入涉及不同文档，当前未使用跨集合事务：已通过授权检查的在途导入可能在并发撤销后完成。撤销完成后发起的新导入会被拒绝；本实现不承诺撤销与所有在途请求在同一事务中提交。

## 第2条用户确认（2026年10月29日）

用户于2026年10月29日确认第2条：同一道题的回答数据在不同问卷所有者之间封闭，原作者和共享接收者不能相互查看对方的答案或统计；跨问卷统计也只合并当前用户自建问卷。撤销仅阻止后续取用，已有问卷、历史回答和统计保留，并可继续填写。
