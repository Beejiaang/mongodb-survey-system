# 填写与答案保存

分享问卷要求先登录。点击“开始填写”或“继续填写”后，系统在 MongoDB 的 `responses` 中创建或恢复本人的 draft 进度。逐题点击“保存并继续”进行服务端校验，按已配置规则跳转；完成后进入确认页，点击“确认提交”转为 submitted，显示本人回执。

分享入口不预览整卷，只有退出及开始/继续填写。刷新或重新登录后，可从原分享入口继续已有进度。尚未点击下一步的输入未保存。答案不放在会话 Cookie 中，也不接受客户端指定用户、路径、正式提交时间或整份答案。

## 题目与返回修改

填写页不常驻展示数字上下限及阿拉伯数字格式的小字说明；这些限制仍由后端校验，不合格时给出具体错误。创建者主动加在题目标题里的数字提示仍保留。单选、多选、文本、数字都复用题型校验。数字先检查阿拉伯数字格式（ASCII 0–9，可带正负号、小数点和科学计数法），再按整数优先解析；零和64位整数保留，全角数字、中文数字、带单位或分隔符、NaN、无穷、超范围和不符合整数要求的答案被拒绝。浏览器先检查格式，服务端仍强制校验；错误时保留输入且不推进进度。“上一题”可跳过当前输入的格式检查。文本原样保存且自动转义展示。

只校验实际经过的题目。被跳过的必答题不阻止提交；选答题确认留空保存为 null。多选“至少包含”和“恰好选择”的语义、优先级与配置试算一致。

“上一题”返回实际路径的上一题，保留原值供修改。再次点击下一步时，清除当前题之后的所有旧答案，重新计算路径并重新填写后续题；确认页仅展示最终实际路径。每次修改以 version 做原子比较，旧标签页不能覆盖更新后的进度。

## responses 文档

一份文档对应一次填写，答案数组嵌入文档，便于整份原子保存。未提交和正式回答共用集合，继续保持 users、surveys、responses 三集合设计。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| _id | ObjectId | 一次填写的稳定编号，也是幂等提交标识 |
| survey_id | ObjectId | 引用问卷 |
| respondent_key | string | 按问卷隔离的内部 HMAC 标识，供权限和防重复使用 |
| user_id | ObjectId / null | 实名关联账号；匿名为 null |
| is_anonymous | bool | 开始填写时复制问卷的匿名设置 |
| allow_repeat | bool | 开始填写时复制问卷的重复设置，用于唯一索引 |
| state | draft / submitted | 未提交进度或正式回答 |
| question_revision | string | 题目和跳转配置摘要，防止填写中配置被外部修改 |
| version | int / long | 乐观并发版本，每次保存、返回或提交递增 |
| answers | array | 有序的 `{question_id, value}`；值为选项编号、编号数组、文本、数字或 null |
| path | array | 当前已保存答案对应的题目编号；正式提交时为完整实际路径 |
| current_question_id | string / null | 正在填写的题目；null 表示确认阶段或已提交 |
| created_at | date | 创建进度的 UTC 时间 |
| submitted_at | date / null | 数据库准入时的 UTC 时间；未提交为 null |

`response_schema.py` 校验字段及类型、匿名身份一致性、状态与提交时间一致性。应用层进一步校验所有权、问卷配置、实际路径和答案语义。正式提交不能再修改。

统计及结果查询必须限定 `state: submitted`，不得把 draft 算作回答。现已提供创建者汇总与单题结果页，见 [统计结果说明](统计结果说明.md)。

## 匿名与重复填写

沿用问卷现有“匿名收集回答”开关：开启后，每份回答的 user_id 都为 null，不保存用户名。内部标识为 `HMAC-SHA256(独立密钥, survey_id:user_id)`；相同账号在不同问卷中的标识不同。创建者结果接口不能返回该标识。它是服务端可关联的伪名标识，不承诺对持有密钥和账号数据的管理员不可关联。

密钥优先读取 `RESPONSE_IDENTITY_KEY` 环境变量，否则首次运行生成在被 Git 忽略的 `instance/response-identity-key`。它与登录会话密钥独立，重启保持不变。部署多实例必须使用同一密钥，备份时应与数据库一起保管；更换需要迁移已有标识，不能直接删除文件，否则无法恢复旧进度或按旧标识防重复。

禁止重复时，部分唯一索引 `one_submission_per_user` 对 `(survey_id, respondent_key)` 生效，过滤条件为 submitted 且 allow_repeat=false。即使同一账号在并发开始时生成两份 draft，也只有一份能正式提交；失败的仍保留为 draft。不同账号互不影响。

允许重复时，提交后重新开始会创建新记录。对同一记录重复提交、重复点击或刷新回执只返回同一份结果，不会多生成一份回答。

另有 `respondent_progress` 索引用于查本人进度，`survey_submissions` 索引用于统计及答案排序。未完成进度目前保留，不自动过期清理。

## 截止与关闭的并发边界

开始和逐题保存会检查开放状态；提交重新验证整卷路径，再对 surveys 执行一次原子 `find_one_and_update`：匹配 published、相同题目和设置，并用数据库的 `$$NOW` 判断 deadline。该操作更新 updated_at，返回数据库时间作为 submitted_at，问卷更新时间因此也包含提交准入活动。

这次原子检查是提交是否被接受的边界：关闭或截止发生在准入前，则拒绝；已准入的请求可完成 responses 写入，即使此后创建者关闭问卷。进度保存中的状态检查不构成提交准入。

当前 MongoDB 单机部署不要求副本集事务。surveys 准入和 responses 转为 submitted 是两个操作，不宣称跨集合事务：如果准入后写入失败，原回答仍为 draft，不进入统计，可在问卷开放时重试；如果写入已成功但网络响应丢失，再次请求能返回原回执。

## 接口

| 地址 | 方法 | 行为 |
| --- | --- | --- |
| /survey/问卷编号 | GET | 登录后展示问卷介绍、题目和开始入口 |
| /survey/问卷编号/start | POST | 创建或恢复本人进度，303跳到填写页 |
| /survey/问卷编号/fill/填写编号 | GET | 显示当前题、确认页或本人成功回执 |
| 同上 | POST | action=next/back/submit，保存并303跳转；已提交记录直接展示回执 |

所有 POST 要求 CSRF；填写操作携带 version。服务端从登录态取账号。答案不合法400并回显输入；无权限或未知记录404；版本或重复提交冲突409；已关闭/截止410；数据库异常503。已保存的本人回执在问卷关闭后仍可读取。

## 初始化与兼容

更新后运行 `python -m flask --app app:app init-db`，为 responses 创建校验与三个索引。旧 responses 无校验且为空时可直接升级；非空未知结构拒绝覆盖，不丢弃旧数据。重复初始化保留所有已存进度与正式回答。users 和 surveys 文档结构保持兼容。
