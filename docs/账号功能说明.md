# 注册登录退出功能说明

本步提供账号网页，复用已有 `users.py` 处理用户名、生成密码哈希和验证密码。用户确认本步先完成注册、登录和退出，问卷创建和填写留待后续实现。

## 页面与请求

| 地址 | 请求方式 | 功能与结果 |
| --- | --- | --- |
| / | GET | 未登录时展示首页；已登录时跳转个人账号页 |
| /register | GET | 展示注册表单 |
| /register | POST | 校验用户名、非空密码和确认密码；成功后 303 跳转登录 |
| /login | GET | 展示登录表单 |
| /login | POST | 查询规范化用户名并验证密码；成功后 303 跳转个人账号页 |
| /account | GET | 显示用户名、北京时间的注册时间；未登录时跳转登录 |
| /logout | POST | 清除登录状态并 303 跳转首页 |

表单校验失败返回 400，重复用户名返回 409，错误账号或密码返回统一提示和 401，数据库不可用返回不含内部连接信息的 503 页面。GET /logout 返回 405，不退出登录。已登录用户访问注册和登录页面时直接跳转账号页。

## 数据流

注册表单 → 用户处理函数 → users 唯一索引与字段校验 → 登录页面。

登录表单 → 同一个用户名规范化函数 → MongoDB 查询 → 密码哈希验证 → 签名会话 → 个人账号页。

用户名不会被当作查询表达式处理；密码不会回填到表单、写入会话或显示在页面中。密码保留首尾空格和大小写，当前未增加额外长度或复杂度政策。

## 登录状态与表单

会话由 Flask 签名，保存用户编号和随机表单令牌。每次需要身份的请求根据编号重新读取用户，并排除密码哈希；用户不存在时清除身份。登录成功会清除旧会话并更换表单令牌，退出会清空会话。

所有 POST 表单都要求匹配当前会话的 CSRF 令牌，来自其他浏览器、缺失、过期或错误令牌的请求返回 400。页面支持浏览器自动填充和键盘操作，Jinja 自动转义用户名。HTML 响应使用 no-store，避免账号信息被页面缓存。

开发密钥保存在被忽略的 `instance/session-key` 中，重启后保持稳定；配置 `FLASK_SECRET_KEY` 时优先使用该值。部署到 HTTPS 环境时应通过应用配置启用安全 Cookie。

## 本步验证

新增 `tests/test_auth.py`，用 Flask 测试客户端访问真实路由，并用独立临时 MongoDB 数据库验证注册、登录、退出、访问限制、重复用户名、密码确认、CSRF、会话更新、用户删除和数据库失败提示。作业数据库不写测试账号。
