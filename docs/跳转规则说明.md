# 单题跳转规则

本步实现创建者的规则配置、保存、排序、删除和试算，以及后端路径计算。每条规则只判断当前题的答案，不支持跨题 AND/OR 组合。填写页面及 responses 保存仍待下一步接入。

## 页面操作

在自己的草稿问卷详情中，先添加题目，再点击单选、多选或数字题下方的“配置与试算跳转”。选择触发条件、条件值和后面的目标题目，点击“保存规则”。可用上移、下移调整优先级，或删除后重新配置。最后一道题没有后续目标，不能添加跳转。已发布和已关闭问卷禁止修改。

下方“试算当前题的跳转”使用已保存规则计算结果，不保存答案。它只展示下一题或流程结束的预计结果；目前还没有实际提交确认页面。

## 多选的两种语义

指定选项为 A、B 时：

| 实际选择 | 至少包含 A、B（contains_all） | 恰好选择 A、B（equals_set） |
| --- | --- | --- |
| A、B | 命中 | 命中 |
| B、A | 命中 | 命中 |
| A、B、C | 命中 | 不命中 |
| A | 不命中 | 不命中 |
| B、C | 不命中 | 不命中 |
| 留空 | 不命中；必答题先报错 | 不命中；必答题先报错 |

“至少包含”要求指定项全部出现，允许额外选择；“恰好选择”要求答案集合与指定集合相等，不允许多选或少选。两者都忽略顺序，不接受重复或不存在的选项。条件至少指定一项；与题目的最少/最多选择数明显矛盾的规则会被拒绝。

两种规则可能同时命中。始终按保存数组从上到下判断，第一条命中生效；若希望恰好 A、B 和 A、B、C 分别去不同题，应把“恰好选择 A、B”放在“至少包含 A、B”前面。

## 其他规则与路径

- 单选支持选中指定选项时跳转。
- 数字支持等于、小于、小于等于、大于、大于等于、闭区间；不接受布尔、NaN 或无穷。
- 文本填空按顺序继续，暂不配置条件。
- 先验证答案的必答、数量、数值范围等限制，再判断跳转。
- 未命中或选答题留空时按顺序继续；末题完成后路径结束。
- 只能跳到同一问卷中后面的题目，不允许自己、前面的题目或不存在的题目，因此不能形成循环。
- `evaluate_path` 从首题重算路径，仅校验和保留实际途经题的答案。被跳过的必答题不阻止完成，其旧答案也不会进入返回结果。
- 缺少答案键表示尚未作答，路径在此停止；显式 `None` 表示确认留空，仍需符合选答要求。`require_complete=True` 会拒绝未完成的路径。

## 数据与接口

规则嵌入 `surveys.questions[].jump_rules`，数组顺序就是优先级，不增加集合：

```json
{
  "condition": {"operator": "contains_all", "value": ["option_a", "option_b"]},
  "target_question_id": "question_3"
}
```

单选 value 为选项编号；多选为编号数组；数字普通比较为数值，between 为 `[下限, 上限]`。使用稳定编号引用，页面展示对应题目和选项文字。

`GET/POST /surveys/<survey_id>/questions/<question_id>/jumps` 要求登录且属于当前账号。POST 需要 CSRF 和当前题目配置 revision。操作为 add、delete、up、down、test。成功保存返回303；错误配置400、无权限或不存在404、非草稿或过期表单409。

revision 是完整题目配置的摘要，保存时再次匹配题目快照及草稿状态。另一个页面修改题目/规则或发布问卷后，旧页面不能覆盖或误删规则。发布时重新验证整卷规则及所有目标。

## MongoDB 兼容性

数据库 validator 按题型约束规则字段、运算符、值类型、多选非空及唯一性。选项是否存在、数值是否有限、前向目标和选择数是否可满足由应用层校验。

更新后运行 `python -m flask --app app:app init-db`。只有与上一版“jump_rules 必须全为空”严格校验完全一致的集合才自动升级，本版接受其所有合法旧文档，不修改业务数据。未知旧校验仍拒绝覆盖；升级可重复执行。原空规则问卷继续按顺序执行。
