# 关键逻辑说明

本文对应“七、提交内容／2.文档”的关键逻辑说明，集中描述实现步骤、这样处理的原因及当前边界。模块分工见 [系统说明](系统说明.md)，请求参数见 [API说明](API说明.md)，集合与索引见 [数据库设计](数据库设计.md)。

## 身份、权限和输入边界

注册与登录共用users.normalize_username：先去首尾空白，检查3～30个ASCII字母、数字、下划线，再转小写。密码不去空白或改大小写，使用带随机盐的scrypt哈希，登录验证哈希；username唯一索引防止并发注册出重复名字。

Flask签名会话保存用户编号和CSRF令牌，不存密码和答案；每次请求重新查询账号。管理查询必须同时满足问卷_id和owner_id，回答查询匹配问卷、回答_id及由当前账号计算的内部标识，不能信任表单传入的身份。无权访问按404处理，避免暴露他人的记录。所有POST先验证会话CSRF，HTML自动转义并设置no-store。

## 配置校验与答案校验

创建题目先build_question补默认值，再验证配置：题目和选项编号有效且唯一、选项不少于两个、上下限关系成立、必答配置存在可填的答案。JSON Schema负责结构与BSON类型，跨字段范围、选项引用、跳转目标与有限数字由应用层负责。

| 题型 | 填写校验 |
| --- | --- |
| 单选 | 一个现有选项编号 |
| 多选 | 有效且不重复的编号列表，数量在闭区间内；上下限相同表示恰好选指定数量 |
| 文本 | 字符串长度满足上下限，按Unicode码点计数；非空文本原样保存 |
| 数字 | 阿拉伯数字格式后转数值，拒绝布尔、NaN、无穷、超出BSON整数范围、越界及不符合整数要求的值 |

未填写用None表示；多选空数组和文本纯空白规范化为None。选答允许None，但一旦填写仍需满足最小限制；数字0不能被当成空。数字字符串先在网页边界解析，数据层validate_answer本身仍拒绝字符串冒充数字。

创建数字题的小字和一键提示帮助创建者选择正确题型；强制检查来自input_type=number及服务端校验，不通过标题是否含提示文字来推断类型。数字平均值只用于数字题，不自动平均普通文本中看似数字的内容。详见 [题型与校验说明](题型与校验说明.md)。

## 条件跳转与路径计算

每条规则只判断当前题，规则顺序即优先级，第一条命中后停止；没有命中或选答留空就顺序前进。单选判断选项相等，多选区分集合包含与集合相等，数字提供比较和闭区间。目标只能指向后面的题目，从配置上排除循环。

例如指定A、B时，答案A+B+C命中contains_all，但不命中equals_set；答案A+B同时命中二者，以靠前规则生效。条件判断之前先执行题目答案校验，不能通过不合法答案触发跳转。

evaluate_path从首题重新计算：遇到尚未提供答案的题目就停止；明确留空的None表示已经回答过该选答题，可以继续。只校验实际经过题目，跳过题即使必答也不影响提交，跳过题的旧答案不进入结果。完整提交使用require_complete=True检查路径已完成。

规则保存带整卷题目摘要revision，更新时同时匹配旧题目数组、owner_id及draft状态；过期页面不能覆盖其他页面刚修改的规则。发布前再次验证整卷目标与配置。详见 [跳转规则说明](跳转规则说明.md)。

## 逐题保存与返回修改

start_response先检查开放、账号和重复限制；已有草稿则恢复，否则创建独立responses文档。每一步保存先核对当前账号、state=draft、version和question_revision，确保该回答使用的题目及匿名/重复设置没有变化。

保存当前题时，从已重算路径取当前题之前的答案作为前缀，再加入本题新答案，丢弃全部后续旧答案，然后重新计算下一题。这样修改前题时，旧分支中的隐藏答案不会遗留到统计。返回上一题本身只改变当前题指针，不保存输入；再次前进时才清理后续答案。

responses.update_one匹配_id、draft和旧version，并在同一条更新中写入字段、递增version。两个页面同时写同一版本时只有一个成功，另一请求返回409；不同回答文档可独立保存。答案保存在MongoDB，刷新或重新登录仍可继续，不受Cookie容量限制。详见 [填写与答案保存说明](填写与答案保存说明.md)。

## 发布、截止与关闭

草稿发布先检查整卷非空且合法、截止时间未过，再用带owner_id、draft、旧题目数组和deadline条件的原子更新写入published与首次发布时间。并发变化导致匹配失败则要求重试，不能把未检查的新内容直接发布。题目发布后锁定，避免答案引用与题目解释发生变化。

deadline按北京时间输入，转换UTC BSON Date，展示时转回北京时间。“已截止”是published且当前时间大于或等于deadline的推导状态，不写成第四个status。取消或延长时间可以重新开放；手动closed不能重新发布。

开始、保存与提交都会检查开放。正式提交还有一次数据库准入：find_one_and_update匹配published、相同题目/设置，并用数据库$$NOW检查deadline，再由$currentDate取得准入时间。关闭和准入都更新同一survey文档，由原子操作顺序确定是否接受：先关闭或先到期则拒绝；已准入的请求可以随后完成回答写入。

## 正式提交、去重和故障处理

提交只使用服务端已保存答案；先重算完整实际路径，再执行准入，最后把该responses文档从draft改为submitted并保存submitted_at。答案、路径、状态、时间和版本在同一个回答文档内更新。

禁止重复时，部分唯一索引对survey_id+respondent_key生效，仅过滤submitted且allow_repeat=false的记录。即使同一账号并发产生两个草稿，也只能有一个正式提交。允许重复时，提交后再次开始会新建一份；对同一已提交记录再次请求返回原回执，不生成第二份，属于记录级幂等。

当前MongoDB单机不使用跨集合事务。surveys准入与responses写入是两个操作：准入后写失败，回答仍为draft，不进入统计；写成功但响应丢失，重试可得到原回执。准入对updated_at的修改不会因后续回答写失败自动回滚，因此updated_at也反映准入活动。不能把这条流程表述为“两个集合一起原子提交”。

并发测试验证双账号互不干扰、同记录重复提交、两份草稿的唯一约束以及关闭/截止与准入的边界；没有以此声称完成大规模压测。每次提交都会写同一问卷的准入文档，热门问卷可能形成竞争；当前连接按请求创建及关闭，后续规模扩大时应通过压测评估连接复用和吞吐。

## 匿名和重复填写标识

respondent_key使用HMAC-SHA256(独立密钥, survey_id:user_id)。同账号在同一问卷的不同填写记录使用同一内部标识，在不同问卷使用不同标识。匿名回答user_id=null，实名保存user_id；两者统计页都不展示账号身份或内部标识。

这使匿名问卷也能恢复进度、限制重复和计算单选人数。它不是对服务器管理员不可关联的完全匿名。RESPONSE_IDENTITY_KEY须持久化，多实例需一致；更换密钥需要同时处理历史标识迁移。

## 统计、平均值与图表

只有当前问卷submitted记录参与汇总。对每题区分reached、answered、blank、skipped：有效答案为实际path中非null的回答；留空=reached-answered；跳过=正式提交总数-reached。

选项计数按每份有效回答是否选中该项累加，表格占比=该项份数/本题有效份数。单选另通过MongoDB按题目和respondent_key去重计算总回答人数；同账号重复提交仍影响份数，但人数只加一次。此人数是账号数，无法识别一人多个账号。

数字用Fraction累计后计算平均值，再用Decimal展示两位小数，避免直接浮点累加或求和溢出；零参与，留空与跳过不参与，无数字显示“—”。普通文本保留原文，不做无意义的平均。

图表复用计数和回答状态；数字分布由MongoDB基于全量正式数字回答bucketAuto生成至多10段，不用第一页20条答案替代全部数据。多选圆形图以总选中次数为分母，表格以有效份数为分母，界面解释差别。图表脚本失败或禁用时显示表格，本地选择记忆只存展示方式。

整卷页汇总所有题；单题页从汇总中选出目标，并对填空答案另外分页。查询不返回身份，原文自动转义。页面的汇总、人数、分布及答案列表为分次读取；新提交持续发生时可能短暂出现不同读取时刻的数据，不承诺冻结快照。汇总要遍历正式回答，当前没有统计缓存；大量数据下需要评估增量汇总。详见 [统计结果说明](统计结果说明.md)。

## 兼容性与验证入口

初始化可重复执行且不清空数据；只升级已知可兼容旧规则，未知或非空无约束结构停止并要求迁移。第一阶段已发布题目锁定，第二阶段若允许修改题目，应先定义答案版本及统计解释，不能直接改原题后继续混用旧答案。

验证命令见 [测试说明](测试说明.md)。业务测试在独立随机MongoDB数据库中运行，覆盖成功、失败、边界、权限和并发。文档一致性测试另核对路由、集合字段与本地文档链接，避免实现变更后提交说明遗漏。
