# 测试用例与验收结果

本文用于“七、提交内容／3.测试用例”，依据本地原始《大作业一.docx》“六、测试要求”整理。原文要求至少包含创建问卷、添加题目、跳转逻辑、校验、提交问卷、统计六类测试，允许自动测试、手工测试或API测试，并明确要求写清测试步骤。本文同时纳入已实现的额外功能。

## 执行环境与复现方法

在项目根目录安装README中的依赖并启动MongoDB。测试使用Python unittest、Flask测试客户端、真实MongoDB，以及Node内置test运行器；不需要启动5000端口服务。数据库用例为每项测试创建随机命名的 `survey_system_test_<uuid>` 数据库并清理，不使用业务库 `survey_system`，不改已有预览库。默认连接本机27017，可用 `MONGODB_TEST_URI` 指定测试实例。数据库不可用会报错，不会当作跳过后通过。

```powershell
.\.venv\Scripts\python.exe -W error::ResourceWarning -m unittest discover -s tests -v
& 'C:\Program Files\nodejs\node.exe' --test --test-reporter=tap tests\result-charts.test.cjs tests\browser-behavior.test.cjs
.\.venv\Scripts\python.exe -m pip check
git diff --check
```

Node路径为当前Windows机器安装路径，其他机器可使用PATH中的 `node`。本文的自动用例用“测试模块.类.方法”定位到代码；单独复现示例：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_jumps.py -v
.\.venv\Scripts\python.exe -m unittest discover -s tests -p test_responses.py -v
```

每个用例独立准备数据，不依赖表格的执行顺序。网页请求先GET页面取得CSRF令牌，再POST表单；有版本或修订字段时使用页面最新值，除非用例故意构造过期表单。创建者A、填写者B均为测试生成的账号，测试密码不用于业务账号。服务层用例直接调用真实函数并读取数据库，非法输入除校验错误外还核对数据库未发生预期外变化。函数级校验失败通常抛出ValueError；网页错误的具体状态码见对应断言和[API说明](API说明.md)。

表格“实际结果”来自本轮对应自动断言，不代表人工浏览器截图验收。一个场景可以对应多个测试和多组subTest输入，因此场景数不等于运行器的测试方法数。自动测试定位列列出主要证据；完整运行日志包含全部测试方法。

## 十、真实跨设备局域网分享验收（手工）

目的：验证原文“把链接发给别人，让别人填写问卷”的跨设备使用过程。Flask测试客户端、同一电脑的不同浏览器或本机访问自己的局域网IP，都不能代替另一台真实设备的连接证据。公网部署不是本用例的前置条件。

### 前置条件与独立环境

准备运行服务的电脑A，以及同一局域网的另一台设备B（手机或电脑）。确认A的局域网IPv4地址、测试端口空闲、Windows防火墙允许该测试端口，且路由器没有阻止设备互访。示例地址192.168.1.50和端口5002仅作说明，必须换成实测值；不要把127.0.0.1、localhost或监听地址0.0.0.0发给设备B。

在新的PowerShell窗口中先切换到项目根目录，再创建专用空库并启动测试服务，避免将验收回答写入业务库。下面使用当前电脑的项目路径；其他电脑需替换为实际克隆目录。若已经在同一窗口设置了本轮测试库名，切换目录后直接执行初始化和启动命令即可，不必重新生成库名。

```powershell
Set-Location -LiteralPath 'E:\db\lab\第一次大作业'
$env:MONGODB_DB_NAME = 'survey_system_test_lan_' + [guid]::NewGuid().ToString('N')
$env:MONGODB_DB_NAME
.\.venv\Scripts\python.exe -m flask --app app:app init-db
```
