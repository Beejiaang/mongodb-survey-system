# 当代数据管理系统：第二阶段项目完成报告

日期：2026年10月22日。第一阶段代码基线60dbd4c，完成标签phase1-complete-20261022；第一阶段报告与PDF保留原阶段内容。第二阶段在同一项目上扩展，沿用Flask、PyMongo、原有三集合、题型校验、跳转、填写、统计和会话保护。

## 一、项目目标与需求变更

用户新增八类需求：独立保存题目、多问卷复用、定向共享、已发布内容固定、版本历史和恢复、多版本共存、使用情况查询、题库及跨问卷单题统计。另要求先补上问卷顺序调整，并明确删题或调序清空整卷跳转；不同版本统计分开，题目使用权与回答数据权限分开。

本阶段恢复规则按用户最后一次明确要求实施：用旧版本内容生成新版本，记录恢复来源，并保留全部历史。不会把恢复简化成只切换默认指针。

## 二、原设计、新问题与调整原因

第一阶段所有题目嵌入surveys.questions，适合整卷读取和固定填写，但题目没有跨问卷身份，无法知道相同题目被重复使用的位置；若让多个问卷直接跟随同一个可变题目，则历史答案会失去原来的题干和限制语义。

因此保留问卷中的完整内容快照，同时增加独立题目身份、不可原地覆盖的版本和题库引用。选题时记录确切来源，新增题目版本只改变题库默认版本，不自动替换问卷。原来已经实现的题型、页面和统计逻辑继续使用，没有重写整个系统。

## 三、MongoDB设计与数据结构变化

| 集合 | 本阶段处理 | 理由 |
| --- | --- | --- |
| users | 原四字段保持不变 | 注册、密码哈希与账号权限继续复用 |
| surveys | 保留原字段及嵌入题目，题目可增加source.question_id/version_id | 既能按来源汇总，又能固定发布时的实际内容 |
| responses | 原结构及答案、路径、摘要保持不变 | 旧回答无需迁移，现有保存与并发控制仍适用 |
| question_items | 新增题目身份、作者、默认版本、共享用户、派生及旧问卷来源 | 管理归属和权限，区分同题与不同版本 |
| question_versions | 新增固定内容、同题版本号、派生源、原默认版、恢复源及说明 | 版本并存，可比较和追溯，不覆盖旧内容 |
| question_banks | 新增名称说明及指定版本条目 | 题库更新由用户显式操作，已创建问卷保持固定 |

题目内容既保存在版本中，也复制到问卷，是为固定历史语义而保留的冗余。题库只存引用，回答不再复制一份题目全文。题目限制和跳转仍由数据配置驱动。字段、schema及全部索引与[数据库设计](数据库设计.md)一致，并有文档测试核对。

从第一阶段问卷保存题目时，在题目库项original_use记录原问卷实例和初始版本，不给旧问卷追加字段。使用查询和统计在本人权限、实例仍存在且内容匹配时纳入原卷。这个处理避免改变旧question_revision而使原填写进度失效。

## 四、程序调整与使用流程

主导航增加“题目与题库”，题型编辑继续复用原页面和questions.py校验。用户可独立创建题目，或从已有问卷保存题目；在草稿详情选择题库和确切版本。题目版本页显示题干、选项、必答和限制，比较表逐项显示新旧差异。

修改操作基于选定版本创建新记录，版本详情列出派生源、原默认版本和恢复来源。恢复v1会生成新的v3等版本，v1/v2仍存在，旧问卷继续使用各自选定内容。版本号通过MongoDB原子递增和唯一索引分配，较慢的小版本不能覆盖已完成的大版本默认指针。

题库支持创建、名称说明修改、加入和移除条目、手动更新指定版本及删除容器。删除题库不删除独立题目、版本或已创建问卷。题库表单携带内容摘要，过期请求冲突，不覆盖新条目。

## 五、跳转、校验和权限

草稿可上移、下移或删除题目，剩余题目编号、选项及校验内容保留。成功调序或删题统一清空全卷jump_rules，页面提示重新配置；首题上移、末题下移、过期表单、越权或发布后操作拒绝。后端原子匹配旧题目数组、归属及draft状态，旧规则表单随后因摘要变化而失效。

题库版本不携带原问卷的跳转目标。导入后在具体问卷配置跳转；原来前向跳转、首条命中、多选至少包含和恰好集合、跳过必答等规则继续有效。数字格式、范围、整数和文本长度校验继续使用原实现。

共享按用户名授予题目各版本的使用和派生权，新增原题版本仍限原作者。共享不授予回答数据访问权；使用情况展示本人问卷详情，题目作者还可查看其他引用问卷的名称、编号和状态，但不能管理问卷或查看回答。撤销共享阻止后续访问源题或导入，已经拥有的问卷副本及其统计继续可用。

## 六、跨问卷统计设计

固定version_id是汇总单位。只读取当前用户自建问卷中submitted回答，并核对answers.question_id位于实际path。选择题统计次数和占比，文本原文分页，数字计算精确平均值及全量分布；选择题图表和数字条形/表格继续复用原脚本，文本不增加图表。

不同版本不混算；同一版本在一份问卷出现多次时，每次实际作答分别计数，但正式提交份数只计一次。原匿名HMAC按问卷隔离，不能直接用于跨问卷账号去重，因此此页面标为“回答次数”，第一阶段问卷内的单选回答人数统计继续保留。来源问卷名称只显示本人可管理的内容，结果不返回账号、user_id或HMAC。

## 八、遇到的问题及解决办法

| 问题 | 处理和证据 |
| --- | --- |
| 原问卷题目没有跨卷身份 | 新增题目和版本集合，问卷保留快照与可选source |
| 给已发布旧卷补source会改变摘要 | 在新题目项记录original_use，原卷和回答不变，专门测试原统计纳入 |
| 序列变化导致原跳转含义失效 | 成功删题或调序清空整卷规则，旧摘要拒绝，编号保持稳定 |
| 并发新增版本或默认指针回退 | 原子分配号码、唯一索引、默认版本号条件更新；六请求并发测试 |
| 恢复后历史来源不清楚 | 新版本同时保留派生源、恢复源和创建时可见的原默认版本 |
| 共享被误当成答案开放 | 授权限定题目，统计再按问卷owner_id过滤，覆盖撤销后本人统计仍可看 |
| 旧全链路断言误把updated_at也冻结 | 提交准入原本会更新时间，改为核对题目和其余固定字段；保留首次和修正日志 |

版本分配、插入和默认指针更新不是跨集合事务，失败时可能有版本号空档或未被题目项引用的版本；指针只在内容已写入后更新。统计仍是多个查询，持续提交时不承诺冻结快照；未开展大规模压力测试。这些限制保留，不用功能测试代替性能结论。
