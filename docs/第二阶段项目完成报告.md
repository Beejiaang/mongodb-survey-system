# 第二阶段项目完成报告（开发记录）

课程：当代数据管理系统；阶段：第一次大作业第二阶段。

## 原设计与新需求

第一阶段题目嵌入surveys.questions，每次填写保存在responses。题型、校验、跳转、发布、填写和统计已经实现。第二阶段需要独立保存和共享题目、版本历史及恢复、题库、使用情况查询和跨问卷单题统计。原设计缺少跨问卷稳定的题目身份和版本来源，需要在原三集合与读写链路上增加题目资源及来源信息。

## 修改原因及计划

现有嵌入题目继续作为问卷固定内容，独立题目与版本用来复用和追溯。恢复旧内容按用户最新要求生成新版本；调序和删题清空整卷跳转。具体计划见[第二阶段开发计划](第二阶段开发计划.md)。

## 当前进度与测试

开发开始前214项Python、16项JS基线通过，现有数据已在本地忽略目录备份。第一阶段PDF由用户改名，内容哈希相同，相关链接同步。后续功能仍按实际验证记录，不能因基线通过记为新增需求通过。

## 兼容性与回归

保留第一阶段代码、问卷快照和答案结构，旧数据中的题目编号、选项编号及回答路径不自动改写。初始化只升级已知兼容校验规则；未知旧结构仍拒绝覆盖。每批修改保存Git提交、补充测试与受影响文档。

## 草稿顺序和删除

在现有问卷详情逐题增加上移、下移和删除表单，沿用登录、归属和CSRF保护。操作保留剩余题目编号、选项和限制，统一清空全卷跳转，页面明确提示重新配置。后端匹配旧题目数组和草稿状态，防止旧表单、并发调序或发布竞争覆盖数据。对应新增5项真实MongoDB测试，包含成功、边界、权限、已发布锁定和并发冲突。

## 题目和版本数据扩展

保留原三集合，新增question_items（题目身份和授权）、question_versions（固定版本和来源历史）、question_banks（题库及固定版本条目）。问卷题目新增可选source，正文仍是问卷内快照。恢复按最新规则复制旧内容成新版本，同时记录派生源、恢复源及原默认版本。共享仅授予使用及派生权，原题新增版本仍限作者；使用列表只展示本人问卷，作者对其他用户只见引用数量。

14项新增真实MongoDB测试已通过：导入同版本生成不同实例、发布快照冻结、分支和恢复、并发版本号、共享与撤销、独立派生、旧题导出不重写原卷、固定题库条目、权限、已知旧schema升级及数据库约束。网页及跨问卷统计后续接入，尚不作为完成。
