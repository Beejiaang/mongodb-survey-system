# 当前功能测试说明

先启动 MongoDB，再在项目根目录执行：

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m pip check
```

测试使用独立的随机名称数据库 `survey_system_test_<随机编号>`。每个数据库只由对应测试创建和清理，不复用或清空 `survey_system`。

| 范围 | 输入或操作 | 预期结果 |
| --- | --- | --- |
| 首页 | GET / | 200、HTML、标题及欢迎文字正确 |
| 用户名规范化 | `  Alice_123  ` | `alice_123` |
| 用户名长度 | 去空白后长度 3、30；长度 2、31 | 前两项接受，后两项拒绝 |
| 用户名字符 | 中文、标点、内部空白、Unicode 易混字母、非字符串 | 拒绝 |
| 用户文档 | 创建有效用户 | 恰含四字段，ObjectId 与 UTC 注册时间正确 |
| 密码 | 正确和错误密码 | 前者验证成功，后者失败 |
| 密码原样处理 | 大小写或首尾空格不同 | 视为不同密码 |
| 随机盐 | 同一密码构建两份文档 | 哈希不同，两个哈希均能正确验证 |
| 三集合初始化 | 对空测试数据库运行初始化 | 三个空集合存在 |
| 重复初始化 | 保存用户后再次初始化 | 原记录保留 |
| 初始化命令 | 使用环境变量指定测试数据库运行 init-db | 正确初始化指定数据库 |
| 结构不一致 | 修改测试库校验规则后再初始化 | 报错并保留原记录和规则 |
| 重复用户名 | 先注册 ` Alice `，再注册 `ALICE` | 第二次写入被唯一索引拒绝 |
| 文档校验 | 缺字段、错误类型、未规范化用户名、明文哈希值 | 数据库拒绝写入 |
| 明文密码字段 | 在有效文档中额外加入 password | 数据库拒绝写入 |
| 保存与读取 | 写入用户后重新查询 | 哈希和 BSON 日期正确，无明文密码 |

## 测试安排在什么环节

| 环节 | 要做的测试与验证 |
| --- | --- |
| 确定需求和设计 | 先列成功、失败、边界情况及预期结果，作为验收标准 |
| 实现每个功能 | 编写对应单元测试，如用户名长度和密码验证 |
| 接入数据库 | 用独立测试数据库验证真实保存、类型、唯一索引和数据保留 |
| 接入网页 | 验证表单、页面跳转、登录状态和错误提示，检查桌面和手机布局 |
| 每次创建 commit 前 | 运行完整自动测试、依赖检查和 Git 差异检查，确认原有功能仍然可用 |
| 每阶段提交前 | 从新环境按 README 启动，完整走一遍已交付业务流程，核对报告和测试记录 |
| 第二阶段修改需求时 | 保留旧测试并补充新需求测试，同时验证旧数据和旧功能兼容性 |

题目配置与单题答案校验的测试已补充；问卷创建接口、跳转、整卷提交和统计的测试在对应功能实现时补充。
