# 问卷创建与保存说明

登录后，从个人账号页或导航进入“我的问卷”，点击“创建问卷”。先填写基本信息并保存草稿，再逐题添加单选、多选和填空题。填空题在同一入口选择“文字”或“数字”。每次保存均写入 MongoDB；刷新页面、退出并重新登录后仍能看到已保存内容。

## 页面与请求

| 地址 | 请求方式 | 功能与结果 |
| --- | --- | --- |
| /surveys | GET | 列出当前用户自己的问卷，按创建时间和编号倒序 |
| /surveys/new | GET | 显示问卷基本信息表单 |
| /surveys/new | POST | 保存完整草稿，成功后303跳转问卷详情 |
| /surveys/问卷编号 | GET | 显示自己的问卷、题目和限制 |
| /surveys/问卷编号/questions/new | GET | 显示添加题目表单；kind参数选择题型 |
| /surveys/问卷编号/questions/new | POST | 校验并追加一道题目，成功后303跳转问卷详情 |

所有页面都要求登录。所有 POST 要求当前会话的 `csrf_token`；未登录访问页面跳转登录，错误表单返回400，他人的问卷、无效编号或不存在的问卷返回404。向非草稿问卷添加题目返回409；数据库故障返回不含连接细节的503。表单验证失败会保留已输入的内容，用户修改后可重试。

## 创建表单与保存内容

表单提交 `title`、`description`、`is_anonymous`、`allow_repeat`。标题去首尾空白后须有1～200个字符；说明去首尾空白后最多5000个字符，可以留空。复选框选中提交 `on`，不选时不提交，后端转换为布尔值。长度上限是本项目采用的输入限制。

`owner_id` 从当前登录用户读取；`_id`、状态与日期由后端生成，不接受表单冒充创建者或自行发布。新问卷固定为 `draft`，`questions` 初始为空，`published_at` 和 `deadline` 为 null，创建时间与更新时间相同，均为 UTC 日期。

`create_survey()` 调用 `build_survey_document()` 校验基本信息，再确认用户存在，最后通过 `insert_one()` 写入 `surveys`。返回的编号用于问卷详情地址。匿名与重复填写选项由填写和提交服务执行。

## 添加题目

题型选择参数 `kind` 接受 `single_choice`、`multiple_choice`、`text`、`number`；保存时使用对应的隐藏表单字段。文本和数字最终保存为 `type=fill_blank`，由 `input_type` 区分。切换题型会清空当前未保存的输入，页面已明确提示。

| 字段 | 适用题型 | 说明 |
| --- | --- | --- |
| title、required | 全部 | 题目内容和是否必答 |
| option_text（重复字段） | 单选、多选 | 默认A、B两行；底部“＋”依次添加C、D，至少两项，每行内容必填；旧options_text换行字段仍兼容 |
| min_choices、max_choices | 多选 | 最少、最多选择数量 |
| min_length、max_length | 文本 | 最短、最长文本长度 |
| min_value、max_value、integer_only | 数字 | 数值上下限及整数要求 |

上下限留空存为 null；数量/长度转换为整数，数字上下限优先转换为整数，否则转换为浮点数，再交由已有题目规则检查。题目和选项的 UUID 编号由服务器生成，用户无需填写编号。保存前使用 `build_question()` 和 `validate_question()`，确保错误配置不写入数据库。

单选、多选的加号在JavaScript启用时直接添加行并聚焦新输入，不丢失已有内容；未启用时提交`action=add_option`返回新行，也不保存。填空的文字/数字切换保留题目与两组限制，只应用选中类型的限制。

统一填空表单旁有数字题说明。点击添加“请使用阿拉伯数字回答”按钮会提交action=number_hint，只返回整理后的表单，不保存题目；从文本题操作时转为数字题并保留标题与必答，已有数字设置保留，重复点击不重复追加提示。确认后仍需点击“保存题目”。这条路径不依赖JavaScript，参数汇总见 [API说明](API说明.md)。

保存采用一条带条件的 `update_one()`：同时匹配问卷编号、当前创建者、draft 状态、题目编号不存在，然后 `$push` 新题并 `$set` 更新时间。不同题目并发保存时不会用整份旧数组覆盖新内容；同一题目编号的并发追加只成功一次。创建时间和原题目保持不变。页面提交成功后重定向，刷新详情不会重新提交表单；主动重复发送添加请求会创建另一道新题，本步未实现请求级幂等令牌。

## 权限与数据库约束

读取详情和追加题目均带 `owner_id` 条件；列表也只查询自己的问卷。列表投影只取题目编号，用于计数，不加载选项和限制。`owner_created_at` 复合索引包含 owner_id升序、created_at倒序、_id倒序。

`survey_schema.py` 定义问卷和嵌入题目的 MongoDB JSON Schema，检查字段完整性、BSON类型、题型匹配和未知字段。题目/选项编号唯一性、跨字段上下限、有限数字等业务条件由应用层执行。数据库不会自动验证 owner_id 引用用户是否存在，因此创建服务另行检查。

运行 `python -m flask --app app:app init-db` 可创建或重复核验集合与索引。对上一版本无校验且为空的 surveys 集合，补上结构校验；对已有不同校验或非空旧集合明确报错，不覆盖旧规则、不删除记录。

## 第二阶段布局调整

草稿详情提供上移、下移和删除，剩余题目编号保持稳定。任何实际调序或删除均清空整卷跳转规则，须重新配置。边界移动拒绝，不清空规则。操作要求当前revision并原子匹配旧题目数组；已发布和关闭问卷继续锁定。

从共享题选题时，须先为当前草稿取得出题者批准或主动授权，选择指定版本；其他问卷不复用此授权。共享来源题目不提供另存为常用题入口。详见[共享申请与审批](题目共享与审批说明.md)。

最新共享范围可选面向用户/部分问卷。用户范围获准后可从原题版本页编辑自己的修改分支，再加入草稿或显式替换草稿原题。替换保留题号并清空全卷跳转，发布后不可替换；不会因保存分支而自动改变问卷。详见[共享与分支说明](题目共享与审批说明.md)。
