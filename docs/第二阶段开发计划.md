# 第二阶段开发计划与已确定规则

依据用户提供的《大作业一：需求变更.docx》，在第一阶段Flask、PyMongo、题型校验、跳转和统计代码上扩展。

## 本轮规则

- 问卷固定使用指定版本，页面展示版本内容及差异，题库更新不自动替换问卷。
- 恢复旧内容生成新版本，同时记录前一当前版本、派生来源和恢复来源。以本轮明确规则为准。
- 草稿删除题目或改变顺序后，清空该问卷全部跳转规则并提示重新配置；已发布及已关闭问卷仍锁定题目。
- 跨问卷统计按版本分开。共享题目的使用权不包含别人的问卷答案访问权；默认只汇总当前用户有权查看的自建问卷。
- 共享接收者可使用版本、派生自己的题目；原题历史只能由原作者新增版本。具体权限选择若有用户补充，以其答复为准。

## 顺序与验证

1. 第一阶段基线：完整214项Python、16项JS通过，备份业务库及保留的跨设备验收库；保留用户重命名的第一阶段PDF，核对内容不变。
2. 草稿顺序与删除：上移、下移、删除、跳转清空；验证边界、权限、发布锁定及过期表单冲突。
3. 题目与版本基础：扩展集合、来源字段和已知结构兼容升级；旧问卷与回答编号不改写。
4. 个人题目保存、导入及版本选择：复用既有题型表单与校验，问卷实例保留完整快照及确切来源。
5. 历史、版本比较、派生与恢复：版本不可原地修改，恢复新建记录；查看使用情况。
6. 定向共享：授权与撤销、共享后使用和派生，原题修改权与答案统计权限隔离。
7. 题库：创建、管理条目、指定版本、手动更新版本和选题。
8. 跨问卷单版本统计：选择题计数、文本原文、数字平均值及分布；只计正式回答和实际路径。
9. 全链路、兼容性和回归：覆盖第一阶段功能，更新第二阶段报告、API、设计及测试材料。
